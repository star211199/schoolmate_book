## 关键坑位（下次注意）

1. **MyBatis-Plus 3.5.9 在本机 Maven 镜像下载的 jar 不完整**（缺 PaginationInnerInterceptor），改用 **3.5.7** 正常。镜像不稳定时需换版本验证。
2. **环境变量 `SERVER__PORT=5345` 会覆盖 `server.port`**（被 IDE 占用），启动必须加 `-Dspring-boot.run.arguments=--server.port=8080`。
3. **Knife4j/springdoc 不能同时用 yml `group-configs` 和 `GroupedOpenApi` bean 声明 default 分组** → 启动报 Duplicate key default。
4. Spring Boot 3 必须用 jakarta 命名空间、MyBatis-Plus 用 `spring-boot3-starter`、Knife4j 用 `openapi3-jakarta` 版。
5. 后台进程（spring-boot:run / npm run dev）必须用 run_in_background 启动，否则随命令结束被回收。
6. 本机 npm install 完成时会触发 safe-delete 批量删除保护而中断，重新执行一次 npm install 即可补齐 .bin 链接。
7. **JWT 拦截器放行路径不能写 `/auth/**`** —— 会把 `/auth/me` 一并放行，导致登录成功后 UserContext 为空、userId=null，前端报「用户不存在」。必须精确放行 `/auth/login`、`/auth/register`。
8. 自测只跑 login 不够，必须覆盖「login → /auth/me → 业务接口」全链路，否则放行类 bug 漏网。
9. **不要用 unplugin-vue-components + ElementPlusResolver 按需导入**：main.js 全量引入后，resolver 仍会在运行时不断发现新组件样式（tabs/date-picker/upload 的 style/css），反复触发 Vite 重新预构建；清理缓存目录文件数超 safe-delete 阈值(50)被拦截 → vite 进程崩溃。解决办法：移除按需插件，显式配置 `optimizeDeps.include`（vue/vue-router/pinia/axios/element-plus/@element-plus/icons-vue）。
10. 清理 `node_modules/.vite` 要用 bash 的 `rm -rf`（不经过 node shim），否则同样被 safe-delete 拦截。
11. **Windows 终端（PS）下 `mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8080` 会被拆词**，报 `Unknown lifecycle phase ".run.arguments=..."`。根治办法：在 pom.xml 的 spring-boot-maven-plugin 配置 `<jvmArguments>-Dserver.port=8080</jvmArguments>`，JVM 系统属性优先级高于 OS 环境变量（可屏蔽 SERVER__PORT=5345 的覆盖），用户直接 `mvn spring-boot:run` 即可。
12. vite 配置 `strictPort: true`，避免端口被占用时静默漂移到 5174。
13. git 命令若超过前台时限会被 SIGTERM，push 慢时改用 run_in_background。

## 内网穿透（natapp 免费隧道 → 5173）

- 隧道 `r8b69acf.natappfree.cc` 映射本地 5173，natapp.exe 与 dev server 同机，**`server.host: '127.0.0.1'` 不需要改成 0.0.0.0**，loopback 可通。
- **真正的拦截点是 Vite 5.4.12+ 的 `server.allowedHosts`**（DNS rebinding 防护）：默认只放行 localhost/IP，外部域名访问报 `Blocked request. This host ... is not allowed`。已在 vite.config.js 加 `allowedHosts: ['.natappfree.cc']` 放行。本机 Vite 版本 5.4.21。
- **后端 8080 无需额外隧道**：前端 axios `baseURL: '/api'` + Vite proxy 把 `/api` 转到 `localhost:8080`，proxy 是 dev server 进程内的服务端请求，仍走本机 loopback。
- 路由为 `createWebHistory`，Vite dev server 自带 SPA fallback，外部可直接访问 `/h5`。
- 安全：`start_natapp.bat` 内 authtoken 为明文（**已脱敏，不入库**），该 token 属可滥用凭据，建议轮换且勿外传。
