### 关键设计决策（值得记住）
- **通知写入必须在事务提交后**（`TransactionUtil.afterCommit`），否则会出现「推送了但事务回滚」的幽灵通知。
  触发点在 `FriendServiceImpl`（申请/通过）、`MomentServiceImpl`（点赞/评论）。
- **`MOMENT_*` 通知的 `bizId` 存 classId，不存 momentId**。因为前端要跳到班级主页的动态 tab，
  存 momentId 还得再查一次「这条动态属于哪个班」。这是「前端决定跳转目标」原则的落地。
- **时光胶囊的内容可见性只看 `now >= open_time`，不看 `status`**。`status` 唯一职责是给定时任务
  提供「SEALED→OPENED」的状态跃迁触发点（通知需要一个「从未知到已知」的边沿）。
  好处：定时任务 60 秒一轮，但到点的信在接口层立刻可读，不用等任务跑。
- **SELF 胶囊对他人返回 404 而不是 403**（连存在性都不暴露）。
- **`@EnableScheduling` 加在启动类**；定时任务单节点串行，集群化需 ShedLock。
- 邮箱验证码存 JVM `Map`（单节点），`spring.mail.host` 不配时 `JavaMailSender` 不会被创建，
  用 `ObjectProvider.getIfAvailable()` 判空降级到「管理员重置」。新增 `GET /auth/mail-reset-enabled`
  让前端决定是否显示邮箱找回入口。

### 顺手修掉一个存储型 XSS（聊天）⚠️
在做通知/胶囊时核对 README 的「内容已转义」声明，发现口径是错的，顺着查出真实漏洞：
- **前端 `ChatView.vue` 用 `v-html="m.content"` 渲染聊天气泡**（为保留换行），
  而该分支只区分 `SYSTEM`/`RECALL`/其他 —— **IMAGE、FILE 与 TEXT 走同一段 v-html**。
- 服务端 `ChatServiceImpl.escapeContent` 此前**只对 TEXT 转义**，于是
  `POST /chat/messages {msgType:"IMAGE", content:"<img src=x onerror=alert(1)>"}`
  会把原始 HTML 存库并推送给对方，对方打开会话即执行脚本。**已实测确认可利用**。
- 修复：`escapeContent` 改为「除服务端专用的 SYSTEM 外一律转义」；
  `sendMessage` 增加类型白名单 `TEXT/IMAGE/FILE`，其余按 TEXT 处理
  （顺带堵住「客户端伪造 SYSTEM 系统提示」）。
- 实测修复后：IMAGE → `&lt;img ...&gt;`；伪造 SYSTEM → 降级 TEXT；正常 TEXT 行为不变。
- `docs/_test_group.py` 补 3 项断言，**45 → 48 项全过**。

**教训**：`v-html` + 「只转义一部分类型」是最容易漏的组合。判断转义是否充分，
要**从渲染端反推**（谁用了 v-html、它覆盖哪些类型），而不是只看服务端有没有调用转义方法。
另外：README/docs 里「所有内容都转义了」这种全局性断言，必须逐条 grep 验证 ——
实际只有 `ChatServiceImpl` 用了 `HtmlUtils.htmlEscape`，留言/评论/动态都是靠前端 `{{ }}` 插值转义。
